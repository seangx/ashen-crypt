# 灰烬地窖（Ashen Crypt）

系统按 Astroloot 复刻，画面与 UI 原创（Phaser 3.90，像素风，文字用 Noto Sans SC）。

## 数值都在 `data/`（数据驱动）
改数值只改这里的 JSON，不用碰代码。以 `_` 开头的键是注释，构建时会被去掉；每张表开头的 `_说明` 写了字段含义。

| 文件 | 内容 |
|---|---|
| `progression.json` | 玩家基础属性、经验曲线、怪物成长（生命 / 伤害 / 经验）、每局击杀数和刷怪节奏、精英、怪物、Boss 及招式、Boss 疲惫、Boss 必掉、起始装备、系统解锁 |
| `loot.json` | 掉率（含词条碎片）、稀有度权重、词条数量、锻造潜力、溢彩档、传奇潜力、品质档位、符文槽权重、符文掉落经验、独特装备保底词条档位规则、背包上限 |
| `craft.json` | 铁砧：每个动作的潜力花费、拆解给的碎片、铸符 |
| `mechanics.json` | 主属性换算、防御、异常状态（碎骨 / 余震 / 感电 / 致盲 / 疫病 / 灼烧）、武器形态细节；`whirl` 段是旋风斩流派（旋身层数、旋风之心、风暴之眼、魂火消耗、流派词条、模拟用的词条和符文优先级）；`soul` 段是所有流派共用的魂火资源条（推关里是灯火）、撤回和紧急撤回阈值、魂火词条 |
| `rules.json` | 改规则效果的参数和文字（核心天赋和独特装备共用） |
| `tree.json` | 天赋树每个节点的效果（大型节点的说明按效果自动生成） |
| `uniques.json` | 独特装备 |
| `runes.json` | 符文（数值公式写法见表头）、符文喂养倍数 |
| `atlas.json` | 墓图、命盘、Boss 祝福 |
| `items.json` | 底材的名字、图标、攻击形态 |
| `ladder.json` | 天梯：密度、精英倍数、怪物修正、进度点数、限时、按剩余时间跳层、宝箱（装备、碎片、铸符、溢彩）、段位、记录条数 |
| `auto.json` | 自动战斗走位（`melee` 段是近战武器：在怪最密处来回穿过，不因怪靠近冲刺，护甲低时后撤）、接管（手动倍率）、自动推层 |
| `camp.json` | 营地：自动刷时在营地停留几秒、设施位置和解锁、分解祭坛的默认规则（按稀有度、旧装备、收藏词条数） |
| `astro.json` | 原作配置表：武器 / 护甲底材按品质的数值、词条档位和物品等级窗口、符文需求和权重。由 `tools/gen_data.py` 生成，重新生成会覆盖手改 |

## 改完之后
1. `python3 tools/build.py`：生成 `ashen-crypt.html`（JSON 写错会直接报出哪个文件哪一行）。
2. `node tools/sim.js --runs 30`（或 `--minutes 60`）：无头推层模拟。走位、冲刺、自动循环、自动推层都是游戏自己的自动战斗；脚本只在两局之间换装、插符文、点天赋。打印每局的游戏内时间、难度变化（“退”= 退层练级中）、胜负、用时、秒伤、护甲、最低血量。
   - `--gear none` 从不换装；`--tree auto` 自动点天赋；`--lock` 锁定层数；`--craft auto` 两局之间用铁砧（贪心）；`--ladder every:5` 天梯开放后每 5 趟推关打一次天梯最高层（连打），`--ladder every:10m` 每 10 分钟游戏时间打一次、每次最多连打 `--ladderCap` 局（默认 3；--build whirl/random 默认就是 every:10m）；`--seed N` 换随机种子（同一份数据同一个种子，结果完全一样）；`--json out.json` 存结果。
   - `--build whirl` 按旋风斩流派玩（天赋先走到旋风之心，左手只拿回旋骨刃，符文和做装按 mechanics.json 的 whirl 优先级）；`--build random` 乱点天赋、乱做装，当对照。每行末尾的“旋 心 眼”表示已有旋身符文、旋风之心、风暴之眼；秒伤按满层旋转算；“魂空”是这局魂火见底的时间占比，结尾汇总推层和天梯各自的占比。
   - `--craft auto` 时分解祭坛按 camp.json 的默认规则在每趟回营地时自动分解；结尾报告每小时带回 / 分解的装备数和碎片数，结束原因里“紧急撤回”是层内血量跌破 soul.returnHpNow。
   - sim.js 加 `--seeds 1,2,3` 会每个种子并行跑一遍，打印每个种子的汇总和中位数（单个种子噪声很大）。
   - sim.js 和 bis.js 都能加 `--override 路径=值`（可写多次），不改 data 文件直接试数值，例如 `--override progression.monsterScaling.knee=20 --override progression.monsterScaling.dmgGrowth2=1.03`。
3. `node tools/bis.js --build whirl,random --levels 30,70,100`：毕业配装测试。按物品等级直接配一身满档装备，报告秒伤、有效生命、平均抗性、天梯能连打到几层，以及前两个流派的比值。
   - 需要 playwright（容器里一般在 `/opt/node22/lib/node_modules/playwright`）；Phaser 用 `tools/vendor/` 里的本地副本（MIT）。

## 代码
- `src/*.js` 按文件名顺序拼接：00 工具，05 常量，10 把数据表接成代码里用的形状，15 天赋树，16 独特装备，17 墓图 / 命盘 / Boss，20 存档，30 物品，32 铁砧 / 熔铸 / 符文喂养，40 属性计算，50 战斗逻辑，52 自动战斗与自动推层，53 天梯，54 营地与分解祭坛，75 画面后处理（辉光、热浪、冲击波、调色；WebGL 下才有），55 音效，60 像素图，70 纹理与控件，80 World 场景，85 UI 场景，99 启动。
- 构建时 `data/*.json` 变成全局的 `DATA.<文件名>`，`DATA_HASH` 是这些数据的哈希（天梯记录里用来标明数值版本）。
- `legacy/`：v2（Bones and Coins 式光圈玩法）的旧版本。
