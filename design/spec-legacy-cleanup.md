# 灰烬地窖 · 遗留系统清理（实现规格）

2026-10-25 · 设计线程 · 状态：**实现规格，交外包**
基于 main a5c82d8（代码 93951f6）。来源：design/system-overview.md 问题清单第 2 条。用户 12:37：“ok，出文档，我找人实现”。

建议的实现顺序：**先做 spec-skill-gems.md，再做本文件，最后做 spec-unlocks.md**。本文件有几处要用到技能石规格里的新东西（副手词条、技能石标签）。

## 0. 目标和原则
早期从 Astroloot 搬来的系统，和现在的核心循环（做装 + 爬天梯，灯火下行供材料）重叠，或者把最大的乘区藏在玩家很难理解的地方。这次的目标是：
- **墓图 / 命盘 / 轮换 Boss 祝福**：“刷更难的图拿更多奖励”交给天梯。墓图词条变成天梯层的随机词缀，命盘和祝福下线。轮换 Boss 本身保留，它是内容。
- **印记（chip）**：下线。原来放在印记上的乘区（暴击伤害、元素总增）挪到副手和头冠。
- **体魄（mass）和时流（time）两个主属性**：下线。主属性只剩 **魂力（energy）**，它和魂火 / 灯火直接挂钩，这是本作自己的东西。
- **力场**：去掉体魄、时流两个，其余保留。

原则：
- 老存档里的东西**不能凭空消失**。能换算的就换算，不能换算的退成词条碎片，并弹出一次说明。
- 一次迁移，存档版本 `S.legacyV = 1`。

## 1. 墓图 → 天梯层词缀

### 1.1 新规则：天梯层词缀
- 天梯第 N 层自带 `floor(N / 15)` 条随机词缀，最多 3 条。也就是 15 层 1 条、30 层 2 条、45 层起 3 条。
- 词缀从现有墓图词缀表（data/atlas.json `maps.mods`）里抽，沿用每条的效果和数值，**去掉“只加奖励不加难度”的那几条**（如果有）。
- **种子**：词缀由 `(赛季种子, N)` 决定，同一层每次进都一样。这样排行榜可比。`赛季种子` 现在写死为 1，放在 progression.json `ladder.seed`。
- **奖励**：每条词缀让通关宝箱 +1 件装备、碎片 +20%。数值放 progression.json `ladder.modBonus: { items: 1, shards: 0.2 }`。
- **界面**：天梯石碑选层时，在层数下面列出这一层的词缀（图标 + 一行说明）。战斗中左上角层名下方小字显示。
- **记录**：天梯记录里加 `mods: [id, ...]`，方便以后排行榜显示。

### 1.2 下线的部分
| 东西 | 处理 |
|---|---|
| 墓图掉落 | data/atlas.json `maps.drop` 设为 0（或从掉落表里删掉）。 |
| 背包里的墓图 `S.maps` | 迁移时每张换 `3 + 词缀数×2` 个随机碎片（按碎片掉落权重抽类型），然后清空。 |
| 推层里使用墓图 | 删掉。推层不再有词缀。 |
| 营地 **墓图台** `atlas` 设施 | 从 data/camp.json `facilities` 删掉。 |
| 底栏菜单 **墓图** `MENU` 里的 `atlas` | 删掉。快捷键顺延。 |
| `unlocks.atlas` | 删掉。 |
| `S.stats.maps` | 保留字段不读，不必迁移。 |

### 1.3 命盘（marble）
- **整个下线**：`S.marble`、data/atlas.json `marble`、命盘界面和它给的掉落 / 经验加成都删掉。
- **迁移**：已经花进命盘的资源按原价退成碎片（按 `marble` 的花费表计算），弹出说明。没法算的话，按“每个已点节点 10 个碎片”退。

### 1.4 轮换 Boss 和祝福
- **4 个轮换 Boss 保留**（`BOSSES`、`bossFor(L)`、招式、配色都不动）。它们是推层和天梯的内容。
- **祝福（boons）下线**：`boonAdds()` 返回空，`ATLAS.boons` 删掉，界面上关于祝福的提示删掉。
  - 原因：按击杀次数永久加属性，是和天梯无关的隐性成长，玩家看不到也不好比。
- `S.bossKills` 保留，以后给成就或图鉴用。
- **补偿**：已经拿到的祝福不退。它们是白给的，下线不会让玩家损失投入。弹出说明里写一句“Boss 祝福已移除，强度交给天梯词缀和宝箱”。

### 1.5 代码位置
- `src/17_atlas.js`：只留 Boss 相关（`BOSS_PAL`、`BOSSES`、`BOSS_BY`、`bossFor`、`BOSS_PAT_N`），其余删掉。文件可以改名为 `17_bosses.js`。
- 天梯词缀新写在天梯模块里（`ladderMods(N)`）。怪物属性结算处（生成怪、算伤害、算掉落的地方）原来读当前墓图词缀，改成读 `run.mods`：推层为空，天梯为 `ladderMods(N)`。
- `tools/sim.js`：天梯模拟用 `ladderMods(N)`，删掉墓图相关参数。

## 3. 主属性：只留魂力

### 3.1 现状（data/mechanics.json 顶部，src/40_stats.js:42–79）
- **体魄 mass**：护甲 +2% / 点（`massArmor`），物理伤害总增 1% / 点（`massKinMore`），加速度 −1% / 点。
- **魂力 energy**：灵障 +2% / 点，冲刺回复，热能元素总增 1% / 点，**魂火上限和回复**（`SOUL.perEnergy`、`regenPerEnergy`）。
- **时流 time**：全局攻速 +1% / 点（`timeFlow`，`P.timeMul`）。
- 来源：词条 `FlatMass` / `FlatTime` / `IncreasedMass` / `IncreasedTime`（astro.json 和 mechanics.json 的映射），力场 `Mass` / `Time`，独特规则，天赋节点 `massInc` / `timeInc`（`15_tree.js:122`）。

### 3.2 处理
- **体魄和时流下线**。理由：体魄的“物理总增”是元素绑定，和标签体系冲突；时流就是攻速，换个名字只会让玩家多学一个概念。
- **魂力保留**，并去掉它的“热能元素总增”（`energyThermalMore` 设为 0）。魂力只管：魂火上限、魂火回复、灵障（护盾）、冲刺回复。这样它就是“灯火属性”。

| 原来源 | 换算成 |
|---|---|
| `FlatMass` X 点 | `armorInc` +2X%（同 `massArmor`） |
| `IncreasedMass` X% | `armorInc` +X/2 %（按体魄常见值约 25 点估算后取整） |
| `FlatTime` X 点 | `aspdInc` +X% |
| `IncreasedTime` X% | `aspdInc` +X/4 %（取整，至少 1） |
| 天赋节点 `massInc` / `timeInc` | 同上换算；节点 id 不变 |

- 词条换算在 `migrateAffs` 里做（存档里的词条换 key 和数值），数据表里把 `FlatMass` 等标 `off: 1`，新掉落不出现。
- `P.mass`、`P.time` 计算保留但恒为 0。`massAccel`、`massKinMore`、`timeFlow` 设为 0。这样代码改动最少，以后确认没用再删。
- 角色面板去掉体魄、时流两行。

### 3.3 力场
| 力场 | 处理 |
|---|---|
| 铁骨力场 Mass | `w: 0`，不再掉落；已有的迁移成 **魂涌力场 Energy**，等级不变 |
| 流沙力场 Time | 同上，迁移成 **魂涌力场 Energy** |
| 魂涌 Energy、回息 Recharge、复骨 Resilience、庇护 Aegis、各抗性力场 | 保留不动 |

### 3.4 用到体魄 / 时流的独特
| 独特 | 原规则 | 新规则 |
|---|---|---|
| 攻城骨弩 BigBertha | `flatPerMass` 每点体魄加物理平伤 | `flatPerArmor`：每 100 护甲 +3–5 物理平伤（最小值，最大值 ×2，同原写法）。其余规则不变 |
| 古鲁瓦克之角 GruvaksHorn | `massAdd` 体魄 +10–20 | 换成 `knockMore` 额外 +30–50%（和原有的击退规则合并成一条：击退 +80–150%）。`pull` 保留 |
| 三相之盾 Arestum | 体魄 / 魂力 / 时流各提高 10–25% | 护甲提高 10–25%、魂力提高 10–25%、护盾每秒回复 +1–2%（`shieldRegenPct`）。名字保留，“三相”变成甲、魂、盾 |
| 巴鲁之石 StoneOfBalu | 体魄 +10–20、提高 20–40%，魂力和时流降低 | 魂力 +10–20、魂力提高 20–40%；代价：攻速降低 10–15%（`aspdLess`） |

- 技能石规格（spec-skill-gems.md §武器归类）会把攻城骨弩、古鲁瓦克之角的底子改成新类别底子，两份规格一起做时以技能石规格的底子为准，规则以本表为准。
- 规则函数在 `16_uniques.js`，新规则 `flatPerArmor` 在 40_stats.js:157 旁边加。

## 4. 迁移（`S.legacyV < 1` 时执行一次）

顺序：
1. **墓图**：`S.maps` 每张换碎片 → 清空。
2. **命盘**：退碎片 → 删 `S.marble`。
3. **印记**：`S.chips` 和背包里的 `kind: 'chip'` 全部拆碎片（独特 +10）→ 删 `S.chips`。
   - 例外：4 件独特印记**不拆**，改成新部位的同 id 独特放进背包（数值按原 roll 保留）。
4. **词条**：全部装备跑一遍 `migrateAffs`，按 §3.2 换算体魄 / 时流词条。
5. **力场**：`Mass` / `Time` 力场改成 `Energy`。
6. 设 `S.legacyV = 1`。
7. 弹出一次说明窗口（游戏风格面板，不是网页弹窗），列出：拆了多少件、退了多少碎片、哪些独特换了部位。

- 天赋树：印记槽节点 id 不变，不退点。
- 迁移代码放在 `src/20_state.js`，和现有的 `affixV`、`treeV` 迁移放在一起。

## 5. 验收
1. 新存档：营地没有墓图台，底栏没有墓图，掉落里没有墓图和印记，角色面板没有体魄和时流。
2. 天梯 15 层有 1 条词缀，30 层 2 条，45 层 3 条，同一层每次进词缀一样；通关宝箱按词缀数多给。
3. 老存档（用 saves/ 里六个毕业存档测试）：
   - 迁移后不报错，背包里没有印记，`S.chips`、`S.maps`、`S.marble` 不存在。
   - 迁移前后用 `tools/bis.js` 的单件 DPS 对比：**流派 DPS 下降不超过 15%**。印记总增被拿走后会掉一些，暴击伤害和 `OffSkillMore` 补回大部分。超过 15% 的流派在提交说明里列出来，交给设计线程调。
4. `tools/sim.js --seeds 1..3` 跑得通，推层、天梯不再读墓图。
