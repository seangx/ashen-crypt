# 灰烬地窖 · 渐进式披露（实现规格）

2026-10-25 · 设计线程 · 状态：**实现规格，交外包**
基于 main a5c82d8（代码 93951f6）。来源：用户 10-25“系统如何做成渐进式披露”，system-overview.md 问题清单第 3 条。用户 12:37：“ok，出文档，我找人实现”。

**前置**：先做 spec-skill-gems.md 和 spec-legacy-cleanup.md。本规格假设技能格、技能石、辅助孔已经存在，墓图、印记已经下线。

## 0. 目标
现在开局就能看到装备、符文、天赋、印记、墓图、副手、天梯石碑（锁着）。新玩家第一分钟要面对七个菜单。目标：
- **开局只有三样东西**：主手、一个技能、往下走。
- **每次新东西出现时，玩家手里正好有一件需要它的东西**。比如第一次掉辅助符文时才出现辅助孔；第一次拿到碎片时才出现铁砧。
- **锁着的东西看不见**，不显示“通关第 N 层后开放”的灰按钮。例外：天梯石碑在营地里提前作为“远处的东西”出现（见 §3.2）。
- 每次解锁有一条**游戏内提示**（屏幕中上方横幅 + 营地对应设施亮一下），提示只出现一次。

## 1. 解锁顺序

| # | 解锁 id | 触发条件 | 打开什么 | 解锁提示（横幅文字） |
|---|---|---|---|---|
| 0 | — | 新存档 | 主手、技能格（自带骨矢 GemBolt Lv1、1 孔）、灯火下行、营地的地窖入口和储物箱、底栏“装备”“手册” | — |
| 1 | `wr` 副手 | 第一次打开 Boss 宝箱（通常第 1 层末） | 副手格；这只宝箱**保底**出一件副手 | 副手：强化你的技能 |
| 2 | `gems` 换技能 | 通关第 3 层；第 3 层 Boss 宝箱**保底**一颗非骨矢的技能石 | 技能石可以替换；装备界面显示技能石列表 | 新的技能石：在装备里替换技能 |
| 3 | `mods` 辅助符文 | 第一次拾取辅助符文（事件） | 技能石的辅助孔显示出来；营地出现**符文台**；底栏出现“符文” | 辅助符文：插在技能石的孔里 |
| 4 | `tree` 天赋 | 通关第 5 层 **且** 角色 5 级 | 营地出现**天赋石像**；底栏出现“天赋”。天赋树先只显示六个区的主干，小团被雾遮住，点到相邻节点时散开 | 天赋：每级 1 点 |
| 5 | `craft` 铁砧 | 第一次获得碎片（事件），最早通关第 3 层 | 营地出现**铁砧**；底栏出现“铁砧”。只有“加词条”“升一档” | 铁砧：用碎片给装备加词条 |
| 6 | `salvage` 分解祭坛 | 通关第 8 层 | 营地出现**分解祭坛**，自动分解默认**关**，打开后按规则；批量拆解页签 | 分解祭坛：回营地时自动拆掉不要的装备 |
| 7 | `ladder` 天梯 | 通关第 10 层 | 天梯石碑点亮可进入；底栏出现“天梯” | 天梯：限时 240 秒，只给宝箱 |
| 8 | `craftAdv` 高级铁砧 | 通关第 15 层 | 铁砧加“洗数值”“移除”；技能石页（打磨品质） | 铁砧：可以洗数值、移除词条 |
| 9 | `glyph` 铸符 | 第一次获得铸符（事件，天梯宝箱） | 铁砧加“铸符”页签 | 铸符：天梯带回的稀有工具 |
| 10 | `feed` 喂养 | 天梯通过第 20 层 | 符文台的“喂养”；技能石喂养 | 喂养：把符文和技能石喂给同类 |
| 11 | `oath` 誓约 | 天梯通过第 30 层 | 铸符“立誓”可用；誓约词条开始掉落 | 誓约：一条强词条，配一条代价 |
| 12 | `fuse` 熔铸 | 天梯通过第 40 层 | 铁砧加“熔铸”页签 | 熔铸：独特 + 稀有 = 传奇 |

说明：
- **事件触发**（拾取、获得）都带一个**层数兜底**，见 §2 的 `depth`。比如碎片可能第 1 层就掉了，但铁砧最早第 3 层才开，避免第一分钟就跳出铁砧。事件先发生时记一笔 `S.pending[id]`，等层数够了再解锁。
- **层数**指已通关的最深层（现有 `S.maxDepth - 1`），和现有 `unlocked()` 一致。
- 第 4 条要“等级 5”是为了让第一次打开天赋时手里已经有 4 点，而不是 1 点。
- 墓图、印记已在遗留清理里下线，不在表里。

### 1.1 和其他系统的配合
- **掉落**：解锁前不掉对应的东西。
  - `mods` 前：辅助符文正常掉（它本身就是触发事件）。
  - `glyph` 前：天梯宝箱里第一次出铸符就触发。
  - `oath` 前：誓约词条不在词条池里。
  - 技能石：`gems` 前不掉落（第 3 层保底那颗就是第一颗）。
- **自动分解**：`salvage` 前不分解任何东西（现在 50_combat.js:938 已经按 `craft` 判断，改成 `salvage`）。
- **自动战斗、灯火**：开局就有，不做披露。
- **紧急返回、提前返回**：开局就有。

## 2. 数据格式（data/progression.json `unlocks`）

```json
"unlocks": {
  "_说明": "...",
  "wr":       { "event": "bossChest", "guarantee": "off" },
  "gems":     { "depth": 3, "guarantee": "gem" },
  "mods":     { "event": "pickRune" },
  "tree":     { "depth": 5, "level": 5 },
  "craft":    { "event": "gainShard", "depth": 3 },
  "salvage":  { "depth": 8 },
  "ladder":   { "depth": 10 },
  "craftAdv": { "depth": 15 },
  "glyph":    { "event": "gainGlyph" },
  "feed":     { "ladder": 20 },
  "oath":     { "ladder": 30 },
  "fuse":     { "ladder": 40 },
  "gear":     {}
}
```

每条可选字段：
| 字段 | 含义 |
|---|---|
| `depth` / `level` / `ladder` | 同现在：都满足才开 |
| `event` | 还需要发生过这个事件（`S.events[event] = true`）。事件名：`bossChest`、`pickRune`、`gainShard`、`gainGlyph` |
| `guarantee` | 解锁那一刻在当前（或下一个）Boss 宝箱里保底一件：`off` 副手、`gem` 技能石（从未拥有过的技能石里抽，偏向新流派） |
| `hint` | 横幅文字（上表最后一列）。放进 data，方便改文案 |
| `fac` | 解锁时要亮一下的营地设施 id（可选，默认按 camp.json 的 `unlock` 字段反查） |

`unlocked(id)` 改为：
```js
const unlocked = id => {
  const u = unlockOf(id); if (!u) return true;
  return S.maxDepth - 1 >= (u.depth || 0) && S.level >= (u.level || 0)
    && (S.ladder ? S.ladder.best : 0) >= (u.ladder || 0)
    && (!u.event || (S.events && S.events[u.event]));
};
```

- 事件在发生处记：`S.events.pickRune = true`（拾取辅助符文）、`gainShard`（任何来源得到碎片）、`gainGlyph`、`bossChest`（打开 Boss 宝箱）。
- **检测新解锁**：在通关一层、回营地、拾取、升级、天梯结算后调用 `checkUnlocks()`：遍历 `unlocks`，`unlocked(id) && !S.seenUnlocks[id]` 的，播横幅、亮设施、写 `S.seenUnlocks[id] = true`，并处理 `guarantee`。
- 横幅：战斗中只排队，**等 Boss 宝箱后的整备界面或回营地时再播**，不打断战斗。一次多条时依次播，每条 2.5 秒。
- 横幅同时写进“手册”的“已解锁”一页（一行一条，带时间），玩家可以回看。

## 3. 界面怎么藏

### 3.1 底栏菜单（`MENU`，src/85_ui.js:19）
- 未解锁的菜单项**不画**（现在是画成灰的 + 悬浮提示）。剩下的按顺序左对齐排，快捷键数字按显示顺序重新编号。
- `openWin(id)` 对未解锁 id 直接返回（现在已经这样）。
- 移动端底部导航同理（design/mobile-ui.md 的 7 格，未解锁的不显示）。

### 3.2 营地设施（data/camp.json `facilities`）
- 设施 `unlock` 字段改成新 id：铁砧 `craft`、分解祭坛 `salvage`（现在是 `craft`）、符文台 `mods`、天赋石像 `tree`、天梯石碑 `ladder`。
- 未解锁的设施**不画**，位置留空地（地面花纹照常）。
- **天梯石碑例外**：未解锁时画成“被锁链缠住、不发光”的石碑，悬浮说明“通关第 10 层后，石碑会亮起”。它是核心目标，要让玩家早看到。
- 设施刚解锁时：亮 3 秒（复用现在的选中光晕），头顶一个小“!”，第一次点开后消失（`S.seenFac[id]`）。

### 3.3 装备界面
- 副手格：`wr` 解锁前不画（现在画成带提示的空格）。
- 技能格：一直有；`gems` 前只显示当前技能，不显示技能石列表和“替换”按钮。
- 辅助孔：`mods` 前技能石上不画孔（数据里孔照常存在）。
- 页签（85_ui.js:421 的 `tabs`）：只显示已解锁的；“拆解”页签改为需要 `salvage`。

### 3.4 铁砧
- `craft`：加词条、升一档。
- `craftAdv`：洗数值、移除、技能石打磨。
- `glyph`：铸符页签。
- `fuse`：熔铸页签。
- 未解锁的按钮和页签**不画**（现在是灰按钮）。

### 3.5 天赋树雾
- `tree` 解锁时：六个区的主干节点（从中心到每个区的第一个大节点）可见，其余被雾盖住（暗色 + 噪点，复用光照图的暗部）。
- 点亮一个节点时，和它相连的节点及其所在小团去雾。
- 雾只影响显示，不影响能否点；搜索框和标签筛选在雾中也能找到节点（找到后该小团去雾）。
- 去雾状态存 `S.treeSeen`（节点 id 列表）。

### 3.6 提示文字里的概念
- 词条、规则、技能说明里提到**还没解锁的概念**时（比如“喂养”“誓约”“熔铸”），在悬浮说明里换成一句“？？？（以后会知道）”。
- 实现：说明文字里用 `{u:feed|喂养}` 这样的标记，渲染时按 `unlocked` 决定显示哪种。第一版只改上表 12 个系统名出现的地方。

## 4. 老存档
- 加载时如果 `S.seenUnlocks` 不存在：
  1. 按现有进度补事件：有碎片或装备上有打造过的词条 → `gainShard`；有辅助符文 → `pickRune`；有铸符 → `gainGlyph`；`S.maxDepth > 1` → `bossChest`。
  2. 计算所有已满足条件的解锁，**直接写进 `S.seenUnlocks`，不播横幅**，不处理 `guarantee`。
  3. `S.treeSeen` = 全部节点（老玩家不加雾）。
- 毕业存档（`?demo=`）同理，全部解锁。

## 5. 工具
- `tools/sim.js` 加 `--unlocks on|off`，默认 `off`（全部开放，结果和现在一致）。`on` 时按本表逐步开放，用来看新手前 30 分钟的节奏。
- 调试：URL 参数 `?unlockall=1` 全部解锁；`?fresh=1` 新存档。

## 6. 验收
1. 新存档开局：底栏只有“装备”“手册”，营地只有地窖入口、储物箱、锁着的天梯石碑。
2. 第 1 层 Boss 宝箱必出副手，宝箱后整备界面播“副手”横幅，装备界面出现副手格。
3. 第 3 层 Boss 宝箱必出一颗新技能石。
4. 第一次捡到辅助符文后，回到整备界面时播横幅，技能石上出现孔，营地出现符文台。
5. 战斗中不弹任何横幅。
6. 老存档和六个毕业存档加载后一切照旧，没有横幅，天赋树没有雾。
7. `node tools/sim.js --unlocks on --seeds 1..3 --minutes 30`：日志里按顺序出现解锁事件，第 30 分钟时至少开到 `salvage`（目标：前 30 分钟解锁 5–7 个系统）。
